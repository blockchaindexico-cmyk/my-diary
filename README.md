# My Diary

A voice journal that turns what you say about your day into something you can learn from.

Tap the mic and talk about your day: how it started, what you did, how you felt. Diary transcribes it, then an AI model reads it for **mood, energy, efficiency, stress, anxiety, connection and sleep**, picks out the **triggers** that lifted or drained you, and folds it into a **living profile** of what's going on in your life. You can see your week (or month, or quarter) on the Insights screen, and talk it all through with an AI companion that remembers your journal.

| Screen | What it does |
| --- | --- |
| **Today** | Big mic button. Choose which day the entry is about (today, yesterday, any of the last two weeks), record, review the transcript, save. You can type instead, or "keep talking" to add more. |
| **Journal** | Every entry, grouped by day, with its mood score and summary. Tap one for the full analysis: scores, emotions, triggers, wins, challenges, gratitude, a reflection and a suggestion. |
| **Insights** | Wellbeing score, mood/energy/efficiency/stress trends, an AI-written reflection on the period, what you felt most, what lifts and drains you, which activities move your mood, streaks. Week / Month / 3 Months. |
| **Ask** | Chat with a companion that knows your profile and journal ("What's been draining me lately?", "What should I focus on this week?"). |
| **You** | Your life profile: headline, current chapter, life areas, patterns, what's working and what isn't, people, goals, habits, and focus suggestions. Plus account settings. |

Light and dark mode, iOS-style design (system fonts, grouped cards, native tab bar with Liquid Glass on iOS 26), haptics, and SF Symbols on iOS with matching Material Symbols on Android.

## How it's built

```
mobile/    Expo (SDK 57) + React Native + Expo Router + TypeScript   → iOS and Android
backend/   FastAPI + SQLModel (SQLite by default) + any AI provider   → the API
```

**Why FastAPI rather than Next.js API routes:** voice entries need speech-to-text, and the best self-hostable option (Whisper via `faster-whisper`) is Python. FastAPI also makes the background analysis jobs and typed request/response models simple.

**The pipeline for a voice entry:**

1. The app records mono AAC audio (`expo-audio`) and uploads it to `POST /transcribe`.
2. The server transcribes it (local Whisper by default; audio is deleted right after) and returns the text for you to review.
3. `POST /entries` saves the text with the day it's about. A background job asks the AI for a structured analysis (scores, emotions, triggers, etc.), reusing your existing trigger and activity labels so patterns stay trackable over time.
4. A second job updates your life profile from your recent entries.
5. Insights are computed from the stored analyses; the period reflection and the chat are generated by the AI on demand. Chat memory is your profile, a one-line digest of every entry from the last 180 days, your three latest entries in full, and older entries that match what you asked about.

## Choosing an AI (free options included)

You don't need a paid API. Pick a provider in the app under **You → AI model** (or in `backend/.env`), paste a key, and choose a model from the provider's live list:

| Provider | Cost | Good to know |
| --- | --- | --- |
| **Google Gemini** (default) | Free tier | Get a key at [aistudio.google.com/apikey](https://aistudio.google.com/apikey). Defaults to `gemini-flash-latest`, Google's alias for its newest Flash model. Free-tier limits are tight (a few requests a minute, and a daily cap), and Google may use free-tier data to improve its products. |
| **OpenRouter** | Free models available | One key ([openrouter.ai/keys](https://openrouter.ai/keys)) for hundreds of models. Tap **Browse models → Free only** to see the ones ending in `:free`. Free models have low daily limits and come and go, and some of their providers may train on prompts. |
| **Groq** | Free tier | Fast open models. Its free Whisper can also transcribe your voice notes (choose it under *Speech to text*). |
| **Ollama** | Free, private | Runs models on your own computer, so nothing leaves it. Install [Ollama](https://ollama.com), `ollama pull` a model, and pick it in the app. Needs a fairly powerful machine. |
| OpenAI, Anthropic Claude | Paid | |
| Other | Depends | Any OpenAI-compatible API (LM Studio, DeepSeek, Mistral, Together, vLLM…): enter its address. |

How it works: providers live in `backend/app/services/llm/`. Everything except Anthropic goes through one OpenAI-compatible client. Free and smaller models are less reliable at returning exact JSON, so the server asks for strict JSON-schema output first, falls back to plain JSON mode and then to instructions in the prompt, and remembers which way works for each model. It then repairs common slips (code fences, prose around the JSON, missing fields, "Positive" instead of "positive") instead of failing the entry. **Test connection** in the app makes one small request so you know a model works before you rely on it.

Only the server's first account (you) can change AI settings. Keys entered in the app are stored on your server and never sent back to the app. If something isn't set up yet, entries, insights and chat say exactly what's missing and link to the settings screen.

With Claude, requests use structured outputs and opt into server-side refusal fallbacks (`fallbacks: "default"`), so a safety-classifier false positive on a heavy entry gets retried on another model instead of failing.

If an entry mentions self-harm or being in danger, the analysis flags it and the app shows a card pointing to local emergency services and [findahelpline.com](https://findahelpline.com). Diary is a reflection tool, not a medical service.

## Run it

### 1. Backend

Needs Python 3.11+.

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # optional: or set up the AI from the app
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`--host 0.0.0.0` lets your phone reach it over Wi-Fi. API docs are at http://localhost:8000/docs.

Settings (`backend/.env`):

| Variable | Default | Notes |
| --- | --- | --- |
| `AI_PROVIDER` | `gemini` | `gemini`, `openrouter`, `groq`, `ollama`, `openai`, `anthropic` or `custom`. The choice made in the app overrides this. |
| `AI_MODEL` | provider default | Blank uses the provider's default (Gemini: `gemini-flash-latest`). OpenRouter, Groq and Ollama have no default: pick one in the app or paste an ID. |
| `AI_BASE_URL` | | Only for Ollama on another machine, or `custom`. |
| `GEMINI_API_KEY`, `OPENROUTER_API_KEY`, `GROQ_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `CUSTOM_AI_API_KEY` | | Keys can also be entered in the app. |
| `CLAUDE_EFFORT` | `medium` | Claude only. `low` is cheaper and faster; `high` is more thorough. |
| `TRANSCRIPTION_PROVIDER` | `local` | `local` runs Whisper on your server (free, audio never leaves it). `groq` uses Groq's free-tier Whisper (much faster on small servers). `openai` is paid. Also changeable in the app. |
| `WHISPER_MODEL_SIZE` | `small` | `base` is faster, `medium`/`large-v3` more accurate. Downloaded on first use. |
| `JWT_SECRET` | auto | Left empty, a random secret is generated into `backend/.jwt_secret`. |
| `DATABASE_URL` | `sqlite:///./diary.db` | Any SQLAlchemy URL (e.g. Postgres). |
| `ALLOW_SIGNUPS` | `true` | Set to `false` once your account exists if the server is public. |

**Want to see the screens before recording anything?** Seed a demo account with three weeks of sample entries (no API key needed):

```bash
python -m app.seed      # sign in as demo@example.com / demo1234
```

### 2. Mobile app

Needs Node 20+.

```bash
cd mobile
npm install
npx expo start
```

Sign up (the first account owns the server), then open **You → AI model** to pick a provider and paste a key.

The app looks for the API on port 8000 of the computer running `expo start`, so a phone on the same Wi-Fi works with no setup. You can also change the server from the sign-in screen, or set `EXPO_PUBLIC_API_URL` (see `mobile/.env.example`).

**Expo Go vs a development build:** everything the app uses ships in Expo Go, so you can scan the QR code and go. To install it as its own app with its own name and icon, make a development build: `npx expo run:ios` / `npx expo run:android`, or `npx eas-cli build --profile development`.

### Using it day to day

For real use, deploy the backend somewhere with HTTPS (Fly.io, Railway, Render, a small VPS behind Caddy) and point the app at it with `EXPO_PUBLIC_API_URL`. Release builds of the app won't talk to plain `http://` servers. With SQLite, mount a persistent volume for `diary.db`.

Usage per entry: two AI requests (analysis plus a profile update). The period reflection is cached until your entries change, and each chat message is one request. On free tiers that's plenty for a personal journal, but a burst of entries can hit per-minute limits; a failed analysis can be retried from the entry.

## Development

```bash
# backend
cd backend && pip install -r requirements-dev.txt && pytest

# mobile
cd mobile && npx tsc --noEmit && npx expo lint
```

The backend tests swap the AI and the transcriber for fakes, and test the provider layer against a mock OpenAI-compatible server, so they run offline.

### API

| Method | Path | |
| --- | --- | --- |
| POST | `/auth/register`, `/auth/login` | Returns a bearer token |
| GET / DELETE | `/auth/me` | Current user / delete account and all data |
| POST | `/transcribe` | Multipart `audio` file → `{ text }` |
| POST / GET | `/entries` | Create (analysis runs in the background) / list (`start`, `end`, `limit`, `offset`) |
| GET / PATCH / DELETE | `/entries/{id}` | Editing the text re-runs the analysis |
| POST | `/entries/{id}/reanalyze` | Retry a failed analysis |
| GET | `/analytics/overview?days=7&end=YYYY-MM-DD` | Averages, daily series, emotions, triggers, activities, streak |
| GET | `/analytics/insight?days=7&end=YYYY-MM-DD` | AI reflection on the period (cached) |
| GET | `/profile`, POST `/profile/refresh` | Life profile |
| GET / DELETE | `/chat/messages` | History / start over |
| POST | `/chat` | `{ message, today }` → the saved message and the reply |
| GET / PUT | `/ai/settings` | Current provider, model, speech-to-text; update them (server owner only) |
| POST | `/ai/models` | `{ provider, api_key?, base_url? }` → the provider's live model list, with free flags where known |
| POST | `/ai/test` | One small request with the saved settings |
